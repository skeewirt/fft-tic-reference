## Purpose

The world map's location-record builder (proposed name WorldMap_BuildLocationRecords; corrected 2026-11-19, it was first read as a shop screen refresh): for every location it accepts, it builds a 64-byte WorldMapLocationRecord (errands on offer, counters, the item categories its shops sell, its state at the current story progress) and puts it into one of the three Locations lists; the location info panel is filled from these records.

## Behavior

- V: it reads event variable 0x90 (144) once and treats a positive value as the flag that adds the poachers' den to the records.
- V: it loops location ids 0 through 0x2E; id 0x2F is skipped entirely.
- V: for each id it calls sub_1401DF4F0 to ask whether the location is available at the current story state; unavailable ids are skipped.
- V: for an available location whose Town has_shop byte (+0x31) is non-zero it calls Shop_BuildItemList five times, as (-1, the location, kind, the list buffer g_MenuList, 0, 0), for kinds 1, 2, 3, 4 and 7 (the loop runs 1..5 and the fifth pass uses 7). Corrected 2026-11-19: an earlier reading gave the kinds as 5, 6, 2, 3, 4.
- V: after each build it walks the returned ids, masks each with 0x3FF and sets a bit in a 0x30-byte stack mask indexed by the item record's category byte at offset 5, but only for categories below 0x23; the 35-byte result becomes record +16 (category_mask).
- V: record dword +0 = errands offered there (Errand_IsOffered over ids 0..95); +4 and +8 = the location's entries of two per-location arrays; byte +12 = no open errand record (Errand_LoadRecord); +52 = location id; +56 = Town sort_order (+0x20); byte +51 = 3 / 2 / 0 when the location is WorldMapProgressInfo town (+8) / town_2 (+0xC) of the current progress row (read through its cache, keys from the GameProgress row) / neither; +61 = location not marked; +62 = Town poachers_den (+0x32) when event variable 144 is above 0.
- V: the record is pushed into the list for Town locations_list (+0x24): list 53 + value for values 0..2, the separate list at +1696 above 2; the three Locations lists (screen +1704 + 32 * i) are insertion-sorted by record +56, then by id; then the list gadget rows are rebuilt (sub_140160BE0).
- I: the mask is the record's category-availability field and is what the location panel shows as 'On' / 'Off' on its 35 category nodes.
