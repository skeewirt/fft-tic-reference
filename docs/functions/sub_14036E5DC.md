## Purpose

The shop screen's refresh: it decides which of the thirty shop slots are open, rebuilds a five-category list for each one to learn which item categories it can show, and redraws the shop gadget and its rows.

## Behavior

- V: it reads event variable 0x90 once and treats a positive value as a screen-mode flag.
- V: it loops shop slots 0 through 0x2E; slot 0x2F is skipped entirely.
- V: for each slot it calls sub_1401DF4F0 to ask whether that shop is available at the current story state; unavailable slots are skipped.
- V: for an available slot it calls Shop_BuildItemList five times with the slot's number and the category bytes 5, 6, 2, 3 and 4, the list buffer at 0x141811470, mode 0 and the sort flag clear; the fifth pass uses category 7 instead of 5.
- V: after each build it walks the returned ids, masks each with 0x3FF and sets a bit in a 0x30-byte stack mask indexed by the item record's category byte at offset 5, but only for categories below 0x23.
- I: the mask is the screen's category-availability record and is what decides which category tabs can be shown, because it is the only result of the five builds that survives the loop.
- V: it reads the errand state (g_ErrandActive) and calls Errand_LoadRecord and a series of nxd table lookups while filling the rest of the screen.
- V: it ends by rebuilding the list gadget rows, using the same entry structure as the other shop screens.
- I: the five builds per slot are a probe, not a display, because their only result that survives is the category bit mask.
- I: the 0x30-slot loop covers every shop the script can open, with 0x2F reserved for the screen's own pseudo-row.
- V: the scratch shop list is read with the 0x3FF mask at 0x14036EB6E after the constant load at 0x14036EB69; this function treats the array as temporary storage for a category census, not as a display list.
