# sub_14006B144

- **Address:** `0x14006B144`
- **Area:** [Save data](../areas/save-data.md)
- **Prototype:** `void sub_14006B144(SaveDataManager *manager)`
- **Callers:** `sub_14006AD04` (one site)
- **Callees:** `sub_14006E5DC` (Documents path), `sub_140073918` (mkdir), `sub_14002620C` (copy), `sub_14006D000`, `sub_14006E460`, `sub_14006EC84`

Confidence tags: **V** decoded, **M** measured, **I** inferred, **?** unknown.

## Purpose

Builds the save folder path once at startup: Documents, the game folder, the profile part and the Steam account id, then creates it.

## Behavior

- V: it starts from the shell's Documents folder, appends a `My Games` segment and the game's folder name (a demo variant is used when a flag byte is set).
- V: it normalises the separators to forward slashes and lowercases the whole string, so every later path comparison is case-insensitive.
- V: it appends the profile part and then `Steam/<account id>/`, the id taken from a call on the Steam user object.
- V: the finished path is stored at manager `+0x430`; the same routine creates the folder through the mkdir helper.
- V: it is called once, from the application's folder setup (`sub_14006AD04`).
- I: the lowercasing is why every literal in the container code is spelled in lower case even though the display names are not.
- ?: what the profile part contains when no Steam user is signed in.
