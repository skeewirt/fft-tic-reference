## Purpose

Agent state 1 of the save/load screen: it creates and shows the saving overlay and loads its layout, queues the screen-entry autosave, and waits for the save queue and the overlay before moving to state 2.

## Behavior

- V: phase 0 calls `sub_1400FB3B0(-1, 0, 0)`, then `sub_1401CA6C4(agent)` allocates an 80-byte `UIAddonSaving` (vtable `0x1407107E8`), attaches it and returns it; the handler stores it at agent `+0x630` and loads UI row 256 into it.
- V: if the overlay's byte at `+0x44` (68) is clear, phase 0 sets its byte at `+0x45` (69) to request the show; the overlay update consumes that request, shows the widget and sets `+0x44` (68) to 1.
- V: phase 1 advances only while the save request manager is absent or its dword at `+0x188` (392) is 0, `sub_1400C480C` returns 0, and the overlay's `+0x44` (68) is non-zero.
- I: `sub_1400C480C` (callee not shown in this body) queues a new autosave: it checks the save-data object, fills two 128-byte strings from text ids `0xF9C` and `0xF9E`, calls `sub_140034C64(g_SaveRequestManager, 6, "AUTOENHANCED")` and stamps `g_SaveManager + 4020544` with the timestamp. It returns 1 when it queued the request and 0 when its precheck declines, so the phase-1 loop runs it until the precheck declines and the save queue has gone idle.
- V: when all three conditions hold, it calls `UIAgent_SetState(agent + 0x48, 2)`.
- V: phase 2 does nothing; the state has no exit work.
- I: the overlay covers the screen-entry autosave, resting on the phase-1 wait and on the later states requesting its hide through byte `+0x46` (70).
