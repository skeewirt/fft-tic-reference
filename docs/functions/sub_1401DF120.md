# sub_1401DF120

- **Address:** `0x1401DF120`
- **Area:** [Event system](../areas/event-system.md)
- **Prototype:** `bool sub_1401DF120(unsigned int textId, int unused, unsigned short width, bool byMessage)`
- **Callers:** `sub_1401DEC14` (one site)
- **Callees:** `sub_140226208` (text decode) or `EventText_FindMessage`, `sub_140220E5C`, `sub_1402B86C4`

Confidence tags: **V** decoded, **M** measured, **I** inferred, **?** unknown.

## Purpose

Answers whether a text needs two or more lines at a given width: it decodes the text, measures it and divides the measurement by the width.

## Behavior

- V: an id of 0xFFFF returns false at once, and a non-zero global word also short-circuits, so the routine answers "one line" while that flag is set.
- V: the text is decoded through the message path when the last argument is set and through the generic text decoder otherwise.
- V: the decoded text is measured by `sub_140220E5C`, which returns a length pair on the stack.
- V: the measured length is divided by the width argument (`sub_1402B86C4`); the quotient plus one for a non-zero remainder is the line count, and the result is whether that count is 2 or more.
- V: one caller, the inline-text walker, which uses the answer to decide a layout.
- I: this is the "does this name wrap" test of the text layout, which is why it takes a width and returns a boolean rather than a count.
- ?: the two stack outputs of the measuring helper (width and height, or line count and height).
