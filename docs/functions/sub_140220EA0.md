# sub_140220EA0

- **Address:** `0x140220EA0`
- **Area:** [Data access](../areas/data.md)
- **Prototype:** `uint16_t sub_140220EA0(TextMeasure *out, const uint8_t *proportional, const uint8_t *text)`
- **Callers:** sub_140220E5C, EventMessage_Task
- **Callees:** `sub_14022138C` (reads the operand bytes of a code), `sub_14022627C` (digit count of a number), `sub_140220E10` (tag helper), `sub_140331E60` (width of one glyph)

Confidence tags: **V** decoded, **M** measured, **I** inferred, **?** unknown.

## Purpose

The message measuring pass: walks a message's byte string (with its argument codes and back-references) without drawing and reports the width of every line, the widest line and the number of lines. EventMessage_Task runs it before it builds and draws the window.

## Behavior

- V: the third argument is the text pointer; the second points at a flag byte: zero means a fixed width of 1 per printable byte, non-zero means proportional text (each glyph width comes from `sub_140331E60`, and the fixed widths below are 6 or 10 by the language record's field at +8).
- V: the first argument is the output record: a pointer to an array of per-line widths (dwords) at +0 with its capacity as a word at +8, a pointer to the widest-line word at +16, a pointer to the line-count word at +24, and a running widest-line word at +32 that it raises.
- V: the argument vector read by the number and name codes is the message argument block at 0x140783210 (a dword per argument); the function advances through it once per consumed argument.
- V: a byte below 0xD0 is a printable character: its width (fixed or glyph width) is added to the current line; a byte whose high nibble is 0xD (0xD0 up to the top of that nibble) also sets a page prefix that the next byte combines with to pick the glyph; bytes of 0xD0 and above that are not handled by a case add no width. the story choice codes (the two bytes just above 0xFA) are not literals in this body and fall into that last group, so they add no width.
- V: code 0xFA adds one fixed width to the current line.
- V: codes 0xE4 and 0xE6 are number codes: they add the printed width of an argument (digit count times the fixed width) to the line; 0xE8 stores an operand used as a digit-count override by the next number code; 0xEE sets the current column from its operand.
- V: the codes found by the range tests `b - 0xE2 <= 1`, `b - 0xF5 <= 1` and `b == 0xEC` (so 0xE2 and its successor, 0xF5 and its successor, and 0xEC; the successors are not literals) are skipped with their operand through `sub_14022138C` without adding width.
- V: before the other tests the tag helper `sub_140220E10` is asked whether the byte plus the current argument stands for a replacement string; when it does, the walk continues in a static replacement string (address 0x14067213C) and then returns to the byte after the code.
- V: a back-reference is a byte whose high nibble is 0xF and low nibble is below 4 (`(b & 0xF0) == 0xF0 and (b & 0xF) < 4`); the next two bytes give a distance, the walk continues that many bytes earlier in the text and returns afterwards. The limit 3 comes from the test, it is not a literal.
- V: code 0xF8 ends the current line: its width is stored in the per-line array (while the line index is below the capacity), the widest-line values are raised, the line index goes up and the column restarts at 0.
- V: a byte above 0xFD (the two top values, reached by the unsigned compare) ends the text unless a back-reference return is pending, in which case the walk resumes at the return point. The compare is `> 0xFD` in the code, so the top value is not an immediate in the body.
- V: when a line ended right after code 0xFA its trailing 0xFA width is taken off before the longest-width test; at the very end one fixed width is added to the widest value when the last line was the widest.
- V: on return writes the widest line width to the word behind the pointer at +16 and the line count to the word behind the pointer at +24, and returns the line count.
- V: at the start it also copies a dword from 0x140723A50 to 0x142FF3CC0 and 16 bytes from 0x1411A7DEC to 0x142FF3CB0 (side effect: two static copies; what they feed is not read here).
- I: the argument-block read at 0x1402210A1 is one consumer of this walk (besides the number codes).
- ?: what the two static copies at 0x142FF3CC0 and 0x142FF3CB0 are used for; ?: the exact difference between the running widest word at +32 and the word behind the +16 pointer.
