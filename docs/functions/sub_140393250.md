# sub_140393250

- **Address:** `0x140393250`
- **Area:** [Items and shops](../areas/items.md)
- **Prototype:** `__int16 *__fastcall sub_140393250(int index)`
- **Callers:** sub_1403934B0, sub_14039415C (installed by the item screen as a row-icon callback)
- **Callees:** Item_GetRecord

Confidence tags: **V** decoded, **M** measured, **I** inferred, **?** unknown.

## Purpose

The item screen's row-icon callback: it maps one list index to the item record's category byte and publishes the two palette bytes and the fixed icon state the row draw reads.

## Behavior

- V: reads `word_141D32F00[index]`, masks it with 0x3FF (`0x140393267`), and reads byte +5 of the item record.
- V: the category byte indexes a two-byte palette table and the two bytes are stored in `word_143D1B578`/`word_143D1B57A`.
- V: it writes the fixed state dword 0xC000C to `dword_143D1B57C`, and copies `word_141D3B9B4` and 31 into `word_143D1B580`/`word_143D1B582`.
- V: the list table is the item screen buffer `word_141D32F00`, not a shop list; the same buffer is filled by `sub_140396FEC`.
- V: the `0x3FF` mask is a ten-bit item-id limit; bit 14 of the entry is dropped by the mask.
- I: the callback shape follows the other item-screen row callbacks that the screen installs next to it.
- ?: the meaning of the two palette bytes and the fixed 0xC000C state.
