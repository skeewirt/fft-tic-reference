# sub_1400D6FB0

- **Address:** `0x1400D6FB0`
- **Area:** [Items and shops](../areas/items.md)

- **Callers:** sub_1401AEEF0, sub_1401AFC20, sub_1401AFDE4, sub_14030AB70
- **Callees:** sub_1400D710C

Confidence tags: **V** decoded, **M** measured, **I** inferred, **?** unknown.

## Purpose

Adjusts the count of one poach type, clamps it, and keeps the two ordered poach lists in step when a type enters or leaves the collection.

## Behavior

- V: the type is the second argument; a type above 96 reads as zero and the function returns without writing anything.
- V: the current count is the byte at 0x1411A7A1A plus the type index, one of 97 entries based at 0x1411A7810 + 522 (reached as base + 0x20A).
- V: the new total is clamped to 99, and if the delta drives it below zero it becomes zero.
- V: the clamped value is written back to the count array whether or not the total changed.
- V: the function compares whether the type was empty before and is non-empty after; only when that state changes does it touch the two ordered lists.
- V: on a change it walks the 97-byte order list at 0x1411A7810 + 619 and the 97-byte sort list at + 716, removing the type from its old position and inserting it at the new one through sub_1400D710C.
- V: the scan of each list stops at 96 entries and shifts the remaining bytes down by one when an entry is removed.
- I: the order list is the player-visible sequence of collected poach types and the sort list is the user reordering of the same sequence, because both hold the same type values and are maintained together.
- I: the 99 cap matches the inventory count cap, which suggests both are the same game rule applied to two stores.
- ?: what the callers pass in the first argument; the function itself never reads it.
