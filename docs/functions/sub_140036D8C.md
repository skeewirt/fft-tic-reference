# sub_140036D8C

- **Address:** `0x140036D8C`
- **Area:** [Save data](../areas/save-data.md)
- **Prototype:** `?`
- **Callers:** `sub_140034D7C` (container writer)
- **Callees:** the PNG library entry points, `sub_14003441C`

Confidence tags: **V** decoded, **M** measured, **I** inferred, **?** unknown.

## Purpose

Writes the finished container into a PNG: it creates the picture, adds the private chunk that holds the container body, and saves it under the formatted `%s.png` name.

## Behavior

- V: the PNG library is libpng 1.6.17, created by the reader/writer pair in this group; this routine is the write half.
- V: the container body goes into a private chunk named `ffTo`; the picture itself is the same 776x436 logo in every file, so there is no per-save thumbnail.
- V: the chunk length is a 32-bit field, so the whole container body must fit in 4 GB (a limit never approached: the largest observed file is a few MB).
- V: it is called from the container writer after the header and the entry table are built and the entries are deflated.
- I: the picture is a fixed asset and not derived from the save, which is why all three containers look identical in an image viewer.
- ?: the chunk-splitting behaviour for a body above the chunk limit was not read.
