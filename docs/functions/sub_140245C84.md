## Purpose

The save-cache clear as a three-step poll: the first call requests the flush, clears the slot cache and reports busy;
the next call reports busy again; a later call reports ready. It is a state machine, not a one-shot clear.

## Behavior

- V: it stores 0 through the status pointer at entry.
- V: state 0 (`dword_142E7FADC == 0`): calls `sub_14033EAA4(0)`, sets the state to 1, fills the 2,008,200-byte
  `g_SaveSlotCache` at 0x142C8B970 with 0xFF, sets the save manager's +260 counter to `3 - (mode != 0)`, and returns 1.
- V: state 1: sets the state to 2 and returns 1.
- V: any other state: clears the state and `byte_1408F9580`, and returns 0.
- V: the return value is a busy flag: 1 means the caller should poll again, 0 means the clear is finished.
- I: the `mode` argument only selects the 3 or 2 written to the save manager's +260 counter; it does not add a second
  clear; nothing in this body selects an auto-slot clear.
- ?: what the +260 counter controls, and what `sub_14033EAA4(0)` does beyond requesting a flush.
