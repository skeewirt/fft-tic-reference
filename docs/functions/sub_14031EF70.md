# sub_14031EF70

- **Address:** `0x14031EF70`
- **Area:** [Items and shops](../areas/items.md)
- **Prototype:** `void sub_14031EF70(void)`
- **Callers:** Game_MainLoop (two calls)
- **Callees:** memset

Confidence tags: **V** decoded, **M** measured, **I** inferred, **?** unknown.

## Purpose

Initialises the item order state at the start of a game: it terminates the five saved item order lists, clears the whole
equipment order block, terminates its five lists, and re-creates the sort-field lists the menu sorters read.

## Behavior

- V: takes no arguments and is called twice from the main loop, both times in the world-init branch after the same preceding
  calls.
- V: writes the value 255 into the first word of each of the five item order lists.
- V: builds a zeroed 1010-byte template on the stack and copies it over the five-list equipment block, which clears all five
  lists at once.
- V: then writes 255 into the first word of each of the five equipment lists.
- V: re-creates six of the eight sort-field byte lists (the two remaining ones are static in the image and are not touched).
- V: also writes a twelve-byte table of small values ending in 255 at a fixed address.
- V: it does not touch the shared display list and does not fill any list with ids; that is the synchronisers' job.
- I: because it clears the equipment block, any in-memory order state before this call is lost; the save load must run after
  it.
- ?: what the twelve-byte table is for; nothing in the order-list code reads it.
