## Purpose

Sorts a 0xFFFF-terminated item list in place by one of eight preset field orders. Before sorting it removes ids the validity
check rejects, so an invalid id never takes part in a comparison.

## Behavior

- V: the second argument is the list; the first is a field selector, masked to four bits.
- V: the selector indexes a table of eight byte lists; each byte names one record field the comparator should use, in order.
- V: the first pass compacts the list: every id the validity check rejects is overwritten by the next entry, so the list
  shrinks.
- V: the second pass is an insertion sort over adjacent pairs; two entries are swapped when the comparator reports the left
  one as not smaller.
- V: the end condition of this function is the 0xFFFF terminator only (compared as the word -1, formed by an OR with -1); it does not use the 255/261 rule of the saved lists.
- V: it reads item records and counts only through the comparator and key helpers; it writes nothing but the list.
- I: this is the sort the player picks in the menu, as opposed to the saved user order maintained by the synchronisers.
- ?: the meaning of each of the eight preset field orders was not established beyond the field keys themselves.
- V: compaction shifts whole words and the sort swaps whole words at 0x140285BF6 and 0x140285BFA; the validity test masks with 0x3FF (constant at 0x140285B4A, mask at 0x140285B4F), so flags travel but do not affect the order.
