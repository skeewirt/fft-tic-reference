# sub_14030E010

- **Address:** `0x14030E010`
- **Area:** [Battle](../areas/battle.md)
- **Prototype:** `int sub_14030E010(int unitIndex, unsigned char *out)`
- **Callers:** sub_1402371F8, sub_1402EB174
- **Callees:** sub_14030DB88, sub_14030E174

Confidence tags: **V** decoded, **M** measured, **I** inferred, **?** unknown.

## Purpose

Builds the battle command list for a unit: it reads the two command-set bytes, maps each command to its kind and lets the per-kind builder fill the list.

## Behavior

- V: It resolves the unit through sub_14030DB88 and returns -1 when that fails.
- V: It reads the command-set bytes at unit+0x12 and +0x13 and rejects a pair whose command kinds do not fit together.
- V: Each command id is mapped to a kind through g_CommandKind (0x14067E010) and masked with 0x0F.
- V: It writes a leading byte to the output and calls sub_14030E174(unit, kind, ...) to append that kind's entries.
- V: Two callers, sub_1402371F8 and sub_1402EB174, the two battle menus.
- V (read 2026-11-12): the output list is a byte array (rdx): g_BattleCommandBytes (0x140D40838, from sub_1402371F8, which stores 0 there first) or g_BattleCommandBytesB (0x14184B2C0, from BattleCommand_BuildUnitList, call at 0x1402EB1A6); these addresses and the call site belong to the callers, the body only receives the pointer; the caller's pointer travels in rdx and r8 inside, so the prototype in the open database shows only the unit index.
- V: list shape: byte 0 = 1; then the primary set (+0x12) unless it is 0 or 0x18; then the secondary set (+0x13) unless 0; then 2 when bit 0x40 and 3 when bit 0x20 of the unit's byte +0x9B is set (both only when +0x63 bit 0x02, Toad, is clear); then the terminator 0xFF. A unit whose +0x65 has bit 0x04, or whose +0x1B4 has bit 0x40 with dword_14185670C zero, gets the list 0xFF alone.
- V: a unit with a monster set (0xB0..0xDF, tested as byte + 0x50 <= 0x2F, in +0x12 or +0x13) is answered early: the list is the primary set alone (0xFF after it), g_BattleCommandKinds[0] = g_CommandKind[set], byte_14184A9A0[0] = 0, and the function returns 1; every other path returns 0 (or -1 when the unit lookup fails).
- V: afterwards, for up to 6 entries until the 0xFF, it writes g_BattleCommandKinds[i] = g_CommandKind[byte] & 0xF and byte_14184A9A0[i] = (sub_14030E174(unit, ...) == 0).
