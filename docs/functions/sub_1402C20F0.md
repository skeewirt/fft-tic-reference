# sub_1402C20F0

- **Address:** `0x1402C20F0`
- **Area:** [UI framework](../areas/ui-framework.md)
- **Prototype:** `int __fastcall sub_1402C20F0(__int64 panel, __int16 unit, int case_id)`
- **Callers:** not in the exported set; an equip change controller
- **Callees:** `Party_GetSlotState`, `Item_CanUnitEquip`, `sub_140289894`, `sub_140288D68`, `sub_140288590`, `sub_140287354`, `sub_1400FB93C`, `sub_1401987F0`

Confidence tags: **V** decoded, **M** measured, **I** inferred, **?** unknown.

## Purpose

Applies an item id to the first slot that does not already hold it and updates the equip block and the stat
readout.

## Behavior

- V: Case 1 finds the slot by raw word equality (`*(u16*)(unit+2*slot+0x54) != id`, 0x1402C20F0 case 1); when
  the item is already equipped it marks the panel byte and returns.
- V: Otherwise it copies the unit to the scratch record (`sub_140289894`), picks a slot with `sub_140288D68`,
  applies the id through `sub_140288590` (masked), then copies the scratch hand words to `g_EquipCandidates`:
  four with a qword move (0x1402C241F) and the fifth with a word (0x1402C242C).
- V: It calls `sub_140287354` with `g_EquipSet` and the candidates, then reads the block's stat words at
  +0x06/+0x12/+0x1C and +0x58/+0x62 for the panel cells.
- V: The raw compare at the first step means a bit-15 word is not seen as the same id.
- I: This is the equip screen's "change one item" path; it writes a committed id, not a flag.
