# sub_1402D7280

- **Address:** `0x1402D7280`
- **Area:** [Unit data](../areas/unit-data.md)
- **Prototype:** `__int64 __fastcall sub_1402D7280(int id_word, int slot)`
- **Callers:** `sub_1402D6914`, `sub_14036BE10`
- **Callees:** `Item_GetRecord`, `sub_140284998`, `sub_140288590`, `sub_140288788`, `sub_1402D6464`, `sub_1402D64CC`, `sub_1402D6FB8`

Confidence tags: **V** decoded, **M** measured, **I** inferred, **?** unknown.

## Purpose

Applies one shop/Outfitter pick to a party unit slot: it refuses a "cannot equip" candidate, removes the old
slot, records the new price, and writes the chosen item id with the session-pending bit 15.

## Behavior

- V: It rejects a candidate with bit 14 set with a bit-14 test (0x1402D72A0) and jumps to the UI state 5 path
  without touching the unit.
- V: It calls `sub_140288788` to validate the id against the unit; a negative result leaves the state at 5.
- V: It reads the current unit word and tests it as signed: a zero test and a negative branch (the export shows the equivalent
  `v7 >= 0` test) decides whether the slot already holds a bit-15 word.
- V: It removes the old word with `sub_1402D6464`, and when the old word was the same masked id it restores
  the override with `sub_1402D64CC` and sets UI state 7 (the "undo purchase" branch).
- V: Otherwise it adds the new item's price to `dword_143D1AC68` and writes `id | 0x8000` to the unit word
  (the constant is loaded at 0x1402D732C, OR-ed at 0x1402D733A, stored at 0x1402D7345), then sets UI state 10.
- V: When the slot is 1 (the second hand) and the unit's new hand pair is one-handed, it repeats the same
  operation with slot 0 (0x1402D743C), so a one-handed weapon fills the other hand too.
- V: It ends in `sub_1402D6FB8` to refresh the preview pairs.
- I: The bit-14 rejection is a list-mark check, not a width check: bit 14 is the shop list's "cannot equip"
  mark and the unit word must not receive it.

## Notes

V: the bit-15 setter. It rejects a candidate with bit 14 (0x1402D72A0), adds the price and writes id | 0x8000 (0x1402D733A). It is called from sub_1402D6914 and the shop message handler sub_14036BE10.
