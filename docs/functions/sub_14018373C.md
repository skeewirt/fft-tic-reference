## Purpose

The load screen's resume-header table: it builds the small object that holds one summary per resume point and fills one entry from each delivered resume payload.

## Behavior

- V: mode 0 allocates a 0x4D8-byte object, constructs it, stores it at ui `+0x628` and hands it to the screen's list helper.
- V: mode 1 inspects the delivered main payload: the magic word `FFTI`, the 0x7A word and a kind below 2 must all hold, otherwise the entry is zero-filled.
- V: a valid payload's 0x108-byte summary is copied into the table at ui `+0x100`, at index `[ui+0x88]`, which the caller advances per point.
- V: the entry stride is 0x108, so the table holds the three resume points plus the battle point without overlap.
- I: the table is what the load screen lists as "continue" entries; a rejected payload leaves a zero entry that the list draws as empty.
- ?: where the index at `+0x88` is reset; the mode-0 branch clears it only when the screen's bit 2 is set.
