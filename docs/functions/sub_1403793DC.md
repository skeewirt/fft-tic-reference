## Purpose

Re-opens a classic menu screen: it prepares the screen of the given kind (27, 28, 29, 43, 44 or 45), then pushes a kind-49 record holding that kind onto the menu screen stack, so ScreenReopen_Step rebuilds the screen on the next steps.

## Behavior

- V: the function takes three arguments: a screen kind and two values that are stored with it in the pushed record.
- V: it calls sub_14033F7B0 with argument 1 and sets bit 0x3800 in a global state dword. That bit is a flag, not a text id.
- V: it calls sub_1402CD758 with argument 0, then tests the kind against 27, 28, 29, 43, 44 and 45 in turn.
- V: the cases are kinds 27, 28, 29, 43, 44 and 45 (0x1B, 0x1C, 0x1D, 0x2B, 0x2C, 0x2D); 27 and 28 pass 544 to sub_14034004C (27 also loads packed block 3), 43 passes 538, 29 passes 544 and loads packed block 4, sets mask 0x800 in the state dword 0x141D32E14 and sets dword_140D49648 to 1 when event variable 146 and any of event variables 420..443 are non-zero; 44 and 45 rebuild their lists (next bullet).
- V: 44 and 45 pass the 92-byte (0x5C) record at the top of the screen stack (0x140D8D8C0, depth 0x140D8DBA0) to their list builders.
- V: every path ends by writing a new record at the current depth: dword 0 = the kind, dword 1 and dword 2 = the two values, dword 4 = 20, dword 5 = 0; it sets the record's stack kind (0x140D4C948) to 49, clears a 0x1E000-byte buffer and three dwords, starts event task 4 with sub_1402B5564, and raises the depth by one.
- V: it returns the address of the kind array 0x140D4C948, a leftover of the last store rather than a result.
- I: kind 49 is ScreenReopen_Step, which rebuilds the screen of the stored kind (its sheet lists the kind-to-builder mapping).
- ?: what the 0x1E000-byte buffer and event task 4 hold during the re-open.
