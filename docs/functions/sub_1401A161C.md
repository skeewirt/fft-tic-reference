## Purpose

The menu screen's decide step: it counts the entries in a list owned by the screen, reads the selected record's kind and switches the screen to the matching sub-state or help page.

## Behavior

- V: it computes an element count from two pointers at screen `+0x3E8` and `+0x3F0` divided by the element size; an empty list returns at once.
- V: it fetches the current record and switches on its dword at `+0x13C`: value 2 sets the screen state at `+0x734` to 0xB, value 3 sets it to 0xC.
- V: for the other kinds it looks up a component by id and, when that component's word at `+0x218` is 10 and its byte at `+0x22A` is clear, tail-calls the help-page setter with id 0x20B.
- V: when a global byte is 8 or more it uses help id 0x20A instead; otherwise it sets the screen state to 6.
- V: it ends by playing cue 0xE through the UI sound routine.
- I: the four record kinds are the errand states (available, dispatched, returning, done), and the two help ids are the "new errand" and "no errand" pages.
- ?: which record table the list points at; the brief counts this as the errand menu's new-flag display, but the table identity was not proven.
