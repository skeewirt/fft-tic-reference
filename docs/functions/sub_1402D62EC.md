# sub_1402D62EC

- **Address:** `0x1402D62EC`
- **Area:** [UI framework](../areas/ui-framework.md)
- **Prototype:** `void sub_1402D62EC(void)` (screen-table handler)`
- **Callers:** none direct; called through the screen table pointer at 0x140680A98
- **Callees:** `EventTask_Start`, `sub_1402C40BC`, `sub_1402C4880`, `sub_1402BDF34`, `sub_14036C49C`, `sub_14036C648`

Confidence tags: **V** decoded, **M** measured, **I** inferred, **?** unknown.

## Purpose

Leaves the Outfitter to the equip screen: it starts the equip task, resets the task slots and switches the
menu state.

## Behavior

- V: On the first call it starts task 2 with `sub_14032D31C`, saves the flag bytes, calls `sub_1402BDF34` to
  reset the task slots, and sets the menu state word to 4.
- V: It then calls `sub_1402C4880(4)` and, when the menu id is 4, `sub_14036C49C`; when it is 5,
  `sub_14036C648`.
- V: If the menu id is non-zero it stores it and switches to state 11; otherwise it switches to state 6 and
  posts the "return" message.
- V: It does not call `sub_1402D65D4` or `sub_1402D5B6C`: no flag is stripped or restored here.
- I: This is a screen transition, not the session commit; the flags stay in memory for the next screen.

## State touched

- Calls: [EventTask_Start](EventTask_Start.md), [sub_14036C49C](sub_14036C49C.md)

## Notes

- V: Because no flag is cleared here, a transition through this handler leaves any bit-15 words in the unit
  records; the next commit/cancel message still has to clear them.
