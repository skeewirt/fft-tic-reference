## Purpose

The load-confirmation handler: it takes the selected slot, asks for its resume parts, loads the slot into the live state and, when the slot was saved in a battle, starts the resume path instead of a plain load.

## Behavior

- V: it reads the slot's situation byte at `+282`; a value of 1 means the slot was written inside a battle.
- V: it requests the resume parts through the read fan-out before loading, so the battle payload is in memory when the load path needs it.
- V: it calls the slot loader, which copies the 40,164-byte slot into the work copy and unpacks it into the live records.
- V: for a situation-1 slot it also calls the resume materialiser, which restores the checkpoint or battle buffer.
- V: it then calls the post-load step that reconciles the checkpoint with the work copy.
- I: the branch on `+282` is the only difference between loading a world slot and loading a battle slot.
- ?: what the callback's second argument carries (the slot index and a confirmation flag were not separated).
