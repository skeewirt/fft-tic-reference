# sub_140033CBC

- **Address:** `0x140033CBC`
- **Area:** [Save data](../areas/save-data.md)
- **Prototype:** `void sub_140033CBC(SaveData *obj, const char *name)`
- **Callers:** `sub_140010750` (settings boot), `SaveSlots_LoadFromFile`, `sub_1400C42E0`, `SaveSlot_LoadToLive`, `sub_1401E7EF8` (5 sites)
- **Callees:** `sub_14002620C` (name copy)

Confidence tags: **V** decoded, **M** measured, **I** inferred, **?** unknown.

## Purpose

Asks the save-file object for one named container entry: it builds a request that carries both the requesting object and the entry name, and queues it so the delivery path can fill the requester's buffer and size later.

## Behavior

- V: the request is a 0x120-byte record; it carries the requester object and a copy of the name, and is pushed on the file object's request list.
- V: the entry is not read here. Delivery happens later and writes the buffer pointer and the size into the requester at `+624` and `+632` (the offsets the resume writer uses) plus the CRC at `+12`.
- V: five call sites: the settings boot path, the manual-slot loader (for `fftsave.bin`), the resume name fan-out, the battle-resume part of a slot load, and the title's Continue probe.
- V: a request while the file object reports busy returns an error instead of queueing, so a second request in the same frame is dropped rather than nested.
- I: the attach member that fills the requester is the same one the writer checks (`+624`/`+632`), so a request whose name is absent simply leaves the requester untouched; the game then sees an empty or damaged slot.
- ?: whether a duplicate request for the same name is coalesced was not read.

## Notes

The read seam of the save system: every resume entry and the manual slot pass through it. The attach member is read indirectly (through the delivery path), not in this function.
