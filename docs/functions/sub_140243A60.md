# sub_140243A60

- **Address:** `0x140243A60`
- **Area:** [Data access](../areas/data.md)
- **Prototype:** `? sub_140243A60(void *node, const char *format)`
- **Callers:** The scene text command path (text command 4)
- **Callees:** memmove

Confidence tags: **V** decoded, **M** measured, **I** inferred, **?** unknown.

## Purpose

The scene text formatter: it composes a text node from a format string and the shared argument vector.

## Behavior

- V: it saves four 16-byte pieces of the current-message argument block into its own state at [node+0x60..0x9F] and restores them on the way out (the four block bases are +0x60/+0x70/+0x80/+0x90; 0x9F is the last byte of the fourth).
- V: the block is 0x40 bytes, sixteen dwords, not two dwords as an older reading had it.
- V: it walks the block four bytes at a time, consuming one dword per format byte, and stops when the tag helper returns -1.
- V: it touches the published list view words and the node's state while composing.
- V: the body's only direct call is memmove, for the 16-byte copies.
- I: this is the formatter behind the command-4 text path, so it is what turns a format string into the visible line.
- ?: which render command or node type it finally produces; 7,834 bytes, read at the block sites only.
