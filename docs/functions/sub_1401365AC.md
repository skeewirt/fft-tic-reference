# sub_1401365AC

- **Address:** `0x1401365AC`
- **Area:** [Event system](../areas/event-system.md)
- **Prototype:** `char sub_1401365AC(UIAgent *agent, unsigned variant, unsigned size, int option)`
- **Callers:** EventMessage_Task (two sites), EventMessage_Scripted (two sites), sub_140135D18 (two sites), sub_140136DB8
- **Callees:** `sub_14013AAC8`, GUICore_FocusNode

Confidence tags: **V** decoded, **M** measured, **I** inferred, **?** unknown.

## Purpose

Gives the input focus to one of the two option nodes of a choice window: the node the message window task calls "the cursor line" while a story choice waits.

## Behavior

- V: first calls virtual slot +16 of the agent (a readiness test); nothing else happens when it returns false.
- V: reads the window object pointer at agent +64 and does nothing when it is null.
- V: `sub_14013AAC8(window, variant, size)` returns the address of one of six sub-blocks of the window object: variant 1 selects the blocks at +656 / +808 / +960, any other variant the blocks at +128 / +280 / +432, and size 0 / 1 / 2 picks the first, second or third of its triple (any other size value gives the first).
- V: only option values 0 and 1 are acted on (the test is unsigned below 2); a larger value leaves the function without a focus change.
- V: the option node is the pointer stored in the chosen sub-block at +136 + 8 * option, or at +120 + 8 * option when the language record exists and its field at +8 is 0 (a language-dependent layout of the two nodes); with no language record the +136 layout is used.
- V: clears byte +132 of the cursor agent (`*(*(qword_143CD9DA8 + 16) + 8)`) when it is set, calls GUICore_FocusNode(option node), then clears byte +557 of that node.
- V: returns the focus call's result; the other branches return the readiness result or the sub-block address.
- V: EventMessage_Task and EventMessage_Scripted call it every frame of the choice loop with the cursor as the option value (the action ids and the choice code belong to the callers, see StoryChoiceBalloon), then call sub_140136654. The same pair is called from sub_140136DB8, whose own body (not this one) tests up / down / confirm actions on a list window, so I: that function is the window class's own list-choice handler and this function is its focus step.
- I: seen live 2026-11-09 at the Mandalia Plain opening: the focused widget during the choice is the event window and the option nodes are two (cursor 0 and 1), matching the unsigned-below-2 test.
- ?: what the +557 byte of an option node means (it is cleared right after the focus call).
