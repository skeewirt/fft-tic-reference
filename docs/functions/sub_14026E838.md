# sub_14026E838

- **Address:** `0x14026E838`

- **Callers:** SceneUnit_BuildFromQueueEntry

Confidence tags: **V** decoded, **M** measured, **I** inferred, **?** unknown.

## Purpose

Battle side of the palette load: copies the classic file's palette into the unit's look pool record, applies the CharShape colour override keyed by the unit's sprite byte, and uploads the palette and frames for the slot.

## Behavior

- V: stores the unit's sprite byte (+0xA) at g_LookPoolFaceValue[pool index (+9)], once in each branch (0x14026E88B and 0x14026E9BB, each after its own byte load of +0xA); the readers take the value as the pool's battle face.
- V: copies the first 0x200 bytes of the file into pool record + 0x30D6 (the lea of 0x140D03676 = pool base 0x140D005A0 + 0x30D6) with the opaque bit 0x80 on every odd byte except byte 1 of each 32 (as CharaPalette_LoadClassic).
- V: calls CharShape_ApplyClut with cl = the sprite byte (a byte load of +0xA at 0x14026E8F3); the copy loop's byte mask of the index with 0x1F (0x14026E8D0) leaves ch = 1 when the loop ends.
- V: slots below 9 upload through sub_140260718, others copy 0x8000 / 0x1000 bytes into fixed buffers; then 12500 bytes of frame data move into the pool record.
- M (unicorn, pristine exe): at the call cx = 0x100 | sprite for every sprite byte 0..255.
- V: in load mode 1 the classic VRAM frame uploads of pools 0..8 (sub_140260718 under `mode != 1`) are skipped; the palette copy into the record (+0x30D6, 512 bytes, then CharShape_ApplyClut), the face value and the record data copy (+2, 12,500 bytes from file +0x9000) run in every mode (the record offsets are computed from the pool base, so +0x30D6 is not an immediate here).
