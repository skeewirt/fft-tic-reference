# sub_140036064

- **Address:** `0x140036064`
- **Area:** [Save data](../areas/save-data.md)
- **Prototype:** `SaveEntryRecord *sub_140036064(SaveDataManager *manager, const char *name)`
- **Callers:** `sub_1400358AC` (the manager's vtable slot 16)
- **Callees:** `sub_14003425C` (inflate), `sub_14003441C`

Confidence tags: **V** decoded, **M** measured, **I** inferred, **?** unknown.

## Purpose

Finds one entry in the container's entry list by name, inflates it and returns its record; it is the name lookup the loader uses for `fftsave.bin`, `settings.sav` and every resume entry.

## Behavior

- V: it compares the requested name against the descrambled names the entry walk produced, and returns only on an exact match.
- V: the payload of the matching entry is inflated here, with the container's preset dictionary, before the record is handed back.
- V: no match means no inflation and an empty result; the caller then sees a requester with no buffer and treats the slot as empty.
- V: it is called once per requested name from the reader state machine, not once per entry in the file.
- I: the exact-match rule is what makes an unknown extra entry harmless on read and useful on write: the loader never asks for it, the writer carries it forward.
- ?: whether a name longer than the 32-byte descriptor field can match was not tested.
