# sub_1401DEC14

- **Address:** `0x1401DEC14`
- **Area:** [Event system](../areas/event-system.md)
- **Prototype:** `?`
- **Callers:** `EventScript_Run`, the new-game path (2 sites)
- **Callees:** `sub_1401DF120` (text fit), `sub_1401DF220`, `EventScript_InstructionLength`

Confidence tags: **V** decoded, **M** measured, **I** inferred, **?** unknown.

## Purpose

Walks the inline text of an event instruction: it steps byte by byte, handles the three control codes it knows, measures each text run and advances to the next instruction.

## Behavior

- V: the walk starts at the script pointer plus an offset and switches on the current byte: 0x10, 0x11 and 0x18 are handled, everything else is text (0x11 and 0x18 are the successive `sub`/`cmp` steps after 0x10, not separate immediates).
- V: it advances instruction by instruction using the shared instruction-length routine, so it stays in step with the interpreter.
- V: it calls the text-fit predicate for the runs it measures and a second text helper for the others.
- V: it is called by the script interpreter itself and by the new-game path, so the same layout code serves a running script and a freshly created game.
- I: the three control codes are line break, page break and a variable or name substitution, which is the classic inline-text set.
- ?: which control code means which of the three; only their values were read.
