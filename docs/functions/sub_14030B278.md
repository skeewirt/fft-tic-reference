## Purpose

Checks whether the unit can answer with an automatic item: it picks one of the two item words the unit carries,
tests that the item is a usable weapon-slot item, and queues the fixed ability `0x1BF` when the test passes.

## Behavior

- V: it loads the unit pointer from `0x14186AF68` and reads the unit's byte at +0x97.
- V: when bit `0x40` of that byte is set it calls sub_14030DD1C and remembers whether the call returned 0.
- V: it returns false when the unit's byte at +6 has bit `0x20` set, which is the monster marker used elsewhere in
  the battle code.
- V: it returns false unless the remembered check passed, so the `0x40` bit and a zero return are both required.
- V: it then reads the byte at battle context +0x18 and returns false unless that byte equals one of a fixed set of
  values in the `0x26`..`0x65` range.
- V: it reads the two 16-bit item words at unit +0x20 and +0x24.
- V: for each word it calls Item_GetRecord and requires the record's slot-flags byte at +3 to be signed-negative,
  which is the weapon-slot bit.
- V: the first item word is accepted only when the byte at context +0x12 is nonzero; the second only when the byte
  at context +0x13 is nonzero.
- V: on success it stores ability `0x1BF` at action +0x10 and returns true.
- V: otherwise it returns false and leaves the action block untouched.
- I: this is an automatic item reaction, because it spends an item the unit carries at fixed record offsets and
  queues a reaction-range ability rather than an action the player chose.
- ?: what the fixed value set and the two context bytes mean.
- ?: whether the two item words are the unit's equipped item slots or a reaction-specific pair.
