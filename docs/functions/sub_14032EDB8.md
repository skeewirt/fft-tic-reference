## Purpose

The flag-aware equip panel task. One function serves two screens: task 9 draws the five Outfitter candidate
words and task 10 draws the five hand words of the equip-screen copy at 0x141876E90.

## Behavior

- V: It reads the current task id from `dword_14184B22C` and branches on 10. Task 10 uses `xmmword_141876EA0`
  (0x141876EA0) and the five words at 0x141876EB4 (0x141876EB4); every other task uses `word_141876C50`
  (0x141876C50), the five candidate words `g_EquipCandidates` (0x141876C64) and `unk_141876C4E` (0x141876C4E).
- V: The first branch also selects a different text bank (the 0x1437F8330/0x1437F6670 pair for task 10, the
  0x1437F9050/0x1437F74D0 pair otherwise), so the carrier and the font are chosen by the same task id.
- V: The hand loop walks five words of the chosen carrier. For each, it masks the id with 0x1FF
  (0x14032F160), skips 0xFF and any value at or above 0x105, and calls the item text/icon path for the rest.
- V: Before the id is used, the same word's bits 14..15 are extracted with a shift right by 12 (0x14032F178) and
  a mask of 0xC (0x14032F17D) and stored in `dword_14184B228` (0x14032F189) for the text draw. The word is
  not masked to ten bits first: the two flag bits are part of the same 16-bit carrier word.
- V: The second loop draws five icons from the same carrier pointer and passes the whole word to
  `sub_1402E1604`; that callee masks again, so a flagged word is drawn by its low nine bits.
- V: The function copies a 1,840-byte text block with `memmove` and clears two 0xD20-byte blocks with
  `memset`; it waits one frame per iteration and ends through `EventTask_Terminate`.
- I: The bit-14 half of the two-bit value is not produced by the Outfitter: the candidate builder marks only
  bit 15. On the task-9 path the value is therefore 0 or 2, not the "cannot equip" mark of the shop list.
- ?: what the stored two-bit value selects in the text draw.
