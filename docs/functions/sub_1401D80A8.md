# sub_1401D80A8

- **Address:** `0x1401D80A8`
- **Area:** [UI framework](../areas/ui-framework.md)
- **Prototype:** `void sub_1401D80A8(void *ui, int slot, unsigned short id)`
- **Callers:** 75 direct sites across every screen (the sound, text and dispatch callers)
- **Callees:** `sub_1401D736C`

Confidence tags: **V** decoded, **M** measured, **I** inferred, **?** unknown.

## Purpose

Sets one UI slot's cue id and dispatches it: the slot number selects the subsystem (sound, text dispatch, and others) and the id selects what that subsystem plays or shows.

## Behavior

- V: it decrements the id and rejects anything above 0x2B1 (689), so the accepted id range is 1 to 690.
- V: an accepted id is passed to the per-slot dispatcher together with the slot index, then stored in the screen's slot array at `+0x9C + 4 * slot`.
- V: slot 10 is the sound cue slot (the sound table reader calls it with the id plus one), and slot 12 is the UI dispatch slot used by one event command class.
- V: the array is part of the screen object, so the last cue per slot is readable after the call.
- V: 75 direct sites make it the single entry point for "show or play this id on this channel".
- I: the 690-entry bound is the size of the largest id space any of the slots uses, which is why it is not per-slot.
- ?: the meaning of every slot number; only slots 10 and 12 were identified.
