# sub_1402888E8

- **Address:** `0x1402888E8`
- **Area:** [Unit data](../areas/unit-data.md)
- **Prototype:** `int sub_1402888E8(unsigned short unit, unsigned short job, int reequip)`
- **Callers:** JobChange_RunPreviewAnim, JobScreen_UpdateState, sub_1403333F0
- **Callees:** Inventory_AddCount, sub_140285A6C, sub_140288A24, sub_1402875A4

Confidence tags: **V** decoded, **M** measured, **I** inferred, **?** unknown.

## Purpose

Sets a party unit's job, returns the old equipment to the inventory and, when asked, equips the best available set for the new job.

## Behavior

- V: the unit index selects the record in g_PartyUnits; the new job id is written to the 16-bit field at record offset 0x24.
- V: when the job changes, the byte at record offset 0x177 is set to 0xFF.
- I: that byte caches a job-dependent value, because it is invalidated exactly when the job id changes and is read again after the re-equip.
- V: when the job id is not 0x5D and the unit is not the special index 0x36, the routine returns each of the five equipment words at record offsets 0x54 through 0x5C to the inventory with a +1 count, then zeroes the words (the loop starts at 0x54, steps by 2 and stops at 0x5E, so the fifth word is 0x5C).
- V: it then rebuilds the unit with sub_140285A6C and sub_140288A24.
- V: when the third argument is non-zero, it calls sub_1402875A4 to pick a new five-piece set, adds each chosen id to the inventory with +1, writes the chosen id into the equipment word and then removes one from the inventory.
- V: the function always returns 1.
- I: the add-then-remove pair around each chosen piece is a way to keep the inventory count consistent when the same id is both returned and re-equipped.
- I: the special cases (job 0x5D, unit 0x36) are units whose equipment is not player-controlled, resting on the fact that they skip both the unequip and the re-equip.
