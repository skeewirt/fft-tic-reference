# sub_140136654

- **Address:** `0x140136654`
- **Area:** [Event system](../areas/event-system.md)

- **Callers:** EventMessage_Task (two sites), EventMessage_Scripted (two sites), sub_140136DB8

Confidence tags: **V** decoded, **M** measured, **I** inferred, **?** unknown.

## Purpose

Shows the finger cursor over the focused option of a choice window once the window's nodes are all built.

## Behavior

- V: reads the window object pointer at agent +64 and does nothing when it is null.
- V: `sub_1400F5828(window + 48, 6, 0, 0)` is true only when the six pointers stored at window +48 are all non-null (a readiness test of the window's six nodes); when it is false the function does nothing.
- V: then looks at the cursor agent (`*(*(qword_143CD9DA8 + 16) + 8)`): it shows the cursor when that agent has no addon at +64, or the addon has no object at +24, or a byte at +74 of that object equals the value left in register r8 (I: zero, since the caller-side setup of the readiness test cleared r8; not confirmed in a debugger).
- V: shows the cursor with UIAgentCursor_Show(cursor agent), then clears byte +132 of the cursor agent when it is set (the pending-show state of the agent).
- V: called right after sub_1401365AC in every frame of the story choice loop (see StoryChoiceBalloon), so the cursor is re-requested each frame while the choice waits.
- I: seen live 2026-11-09 at the Mandalia Plain opening: the finger cursor is drawn at (575, 183) on option 1 and (575, 235) on option 2 only while a choice waits, which is what this function produces; the tools use that as the recognition together with the event window focus.
- ?: whether the byte +74 test can fail (a case where the cursor is not shown although the nodes are ready).
