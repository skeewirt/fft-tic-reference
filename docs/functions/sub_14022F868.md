## Purpose

The action list menu: a scene task that lists a unit's actions and reads the chosen cell.

## Behavior

- V: it is a scene task: it starts and terminates child tasks and waits frames between updates.
- V: it owns a GUI list component and asks the UI core whether the cursor targets an item.
- V: it reads the shared list object's cell words at three sites, the same 2-byte cells the command and ability lists use.
- V: it reads ability aux records and job records while it fills the rows, so the list is made of actions or abilities.
- V: input is read through the action-mapped test helpers rather than raw buttons.
- V: the string ListAction is in its data, and it writes the text-command state block at 0x140D40960..0x140D40978: the word at 0x140D40960, zero at 0x140D40962, the dwords at 0x140D40968/0x140D4096C and the selected word at 0x140D40978.
- I: the unit's action list screen (job or battle), where each row is an ability with its cost and help.
- ?: which screen hosts it; the scene task is started by menu code that was not enumerated.
- V (2026-11-10): the unit is g_PreviewUnitTable + 512 * HIWORD(dword_1407DCF98) when that word is 0..20, else null; two places load its job byte (+3) as the unit's job: 0x14022FFEE (movzx r14d) and 0x140231673 (movzx esi); when the screen's tab index (GlobalWork +5612, 1..7) names a skillset in qword_140D40838, UnitWork_FindJobBySkillset(unit, skillset) answers the job instead. That job feeds the keys of its JobRecord_FromJobId calls (0x14023016E, 0x1402304C4, 0x140231781, 0x14023184C).
