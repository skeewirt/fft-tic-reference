# sub_1402D746C

- **Address:** `0x1402D746C`
- **Area:** [UI framework](../areas/ui-framework.md)
- **Prototype:** `__int64 __fastcall sub_1402D746C(int id, __int64 slot, __int64 unused)`
- **Callers:** `sub_1402D7280`, `sub_14036B670`, `sub_14036BE10`

Confidence tags: **V** decoded, **M** measured, **I** inferred, **?** unknown.

## Purpose

Applies an id to a slot, then mirrors the selected unit's four hand words and the fifth word from the scratch
record into the candidate array and refreshes the stat block.

## Behavior

- V: It calls `sub_1402D7584(&v8,1,1)` (0x1402D749B) to snapshot all five unit words with overrides
  substituted for empty and pending slots.
- V: When the id is non-negative it calls `sub_140288590(0x36,slot,id)` (0x1402D74B7); a return other than 1
  triggers a second call with the unit's current word if it differs from the scratch record (0x1402D74DA).
- V: It copies `qword_141801100 + 0x54` to `g_EquipCandidates` with a qword move (0x1402D7501/0x1402D7506) and the
  word at +0x5C to 0x141876C6C (0x1402D750E/0x1402D7513). The copy is raw, so a bit-15 word travels.
- V: It calls `sub_140287354` to rebuild the stat block (0x1402D753A) and `sub_14036C320` to refresh the
  two-handed/detail state.
- V: It writes the snapshot back to the unit's five words after the refresh, so the override substitution is
  undone.
- I: This is the shop's "equip from the list" path: the scratch record is the source of truth for the displayed
  candidates, while the unit keeps its original words until the commit.
