# sub_1402D7584

- **Address:** `0x1402D7584`
- **Area:** [Unit data](../areas/unit-data.md)
- **Prototype:** `void *__fastcall sub_1402D7584(void *out, unsigned __int8 extra, char substitute_zero)`
- **Callers:** `sub_1402D5CC4`, `sub_1402D6914`, `sub_1402D746C`
- **Callees:** `memmove`

Confidence tags: **V** decoded, **M** measured, **I** inferred, **?** unknown.

## Purpose

Copies the selected unit's equipment words to a caller buffer and substitutes the override word for any word
that is session-pending (or, with the third argument, empty).

## Behavior

- V: It copies `2*extra + 8` bytes from unit +0x54 with `memmove` (0x1402D75CA), so `extra=0` copies four
  words and `extra=1` copies all five.
- V: It then walks `extra + 4` words. A word compared with zero and found negative (a signed comparison of the unit word with zero at
  0x1402D75E1 and a signed branch at 0x1402D75E6) is replaced by the override word (0x1402D7614).
- V: With `substitute_zero != 0` it also replaces a zero word when the override is non-zero (0x1402D7606 and
  0x1402D7612).
- V: The override source is `g_UnitEquipOverride` at 0x14184A680, indexed five words per selected unit.
- I: The buffer is a backup snapshot before a temporary edit; the caller restores it afterwards, so the
  substitution is a preview, not a lasting change.
