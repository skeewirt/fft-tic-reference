## Purpose

Builds the item screen's 256-word list `word_141D32F00` for one category: it walks the item-id space, keeps the owned ids of the category, marks preview-unequippable entries with bit 14, terminates the list, and optionally applies the saved order list.

## Behavior

- V: the loop index runs 1 to 260 (`0x14039711F`); an id is considered only when `g_InventorySnapshot[id & 0x3FF]` is non-zero (`0x14039702F`).
- V: `Item_MenuCategory(id)` selects the category; the branch compares it with the requested group, including the special mappings 0..7 used by the screen.
- V: when `a6` is non-zero it calls `Item_CanUnitEquipPreview(0, id, 2)`; for `a6 == 1` an unequippable id is written with bit 14 set, for `a6 == 2` it is dropped.
- V: each accepted id is written as a word to `word_141D32F00`; the list stops at 145 entries (`v10 >= 145`) and is terminated with the word 0xFFFF, written as -1.
- V: when the requested order is one of the saved groups, it calls `sub_140396748(group)` to apply that order list.
- V: otherwise it walks the built list, drops ids `Item_IsValidId` rejects, and sorts the remainder with the comparator table `qword_1406931C0`.
- V: the 0x3FF on `g_InventorySnapshot[id & 0x3FF]` is redundant because the loop index is below 261; the `0x3FF` on `v17[v19] & 0x3FF` drops bits 14/15 of a list entry.
- I: the list is the item screen's display buffer, not a saved list; it is rebuilt each time the screen opens.
- ?: the meaning of the `a6` modes at the call sites; the comparator table's exact ordering.
