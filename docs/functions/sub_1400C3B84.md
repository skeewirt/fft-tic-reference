- **Address:** `0x1400C3B84`

- **Callees:** `sub_1400C3DBC`, `sub_1400C4198`, `sub_140034C64`, `sub_1403DBE88`

Confidence tags: **V** decoded, **M** measured, **I** inferred, **?** unknown.

## Purpose

The per-frame resume flush: it turns every dirty resume group into named entries, rotates the three-point ring and kicks the autosave container write.

## Behavior

- V: group 1 (world) dirty writes the single `resume_enwm_main.sav` entry.
- V: group 3 (battle) dirty writes the four `resume_enbtl_*` entries (world, attack, fturn, main) in that order.
- V: group 0 (main) dirty writes the four `resume_enNN_*` entries at the next ring index and advances the three-point ring.
- V: after the groups it calls the named-entry queue walk, then one write kick for the `AUTOENHANCED` area if anything was queued, and stamps the manager.
- V: it runs once per frame from the main update, so a capture made during a frame is on disk by the end of that frame.
- I: the order (groups 1, 2, 3, then 0) is what makes `main` the last entry written, which the reader relies on to know the newest part.
- ?: what the boot argument changes; the one call site is the boot update and passes a value that was not decoded.
