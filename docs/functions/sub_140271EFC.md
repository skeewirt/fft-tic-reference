## Purpose

Rolls which abilities a unit learns from the unit on the tile it names; fills the result block at dword_1411A6AB0 and returns its address.

## Behavior

- V: the other unit is Battle_IsTileOccupied(a1 +79, a1 +80, a1 +81 >> 7, 65); above 20 (no unit) the result word is -1. Otherwise that unit is battle record `slot` of g_PreviewUnitTable (512 bytes each) and the slot goes to byte_1411A6B0A.
- V: clears 19 bytes from unk_1411A6B4E and 19 qwords 64 bytes apart from unk_1411A6B61; when the other unit's +98 bit 0 is set the result word is 4 and word_1411A6B0C = sub_1402723EC(that unit), and nothing is rolled.
- V: the result word is 2; nothing is rolled when either unit has bit 0x20 of +6 set.
- V: walks the job indices 0..18 (the loop bound 19 is compared at 0x140272294) with the job id 74 + index; index 0 runs only when both units have the same character byte (+0) and then uses that byte as the job when it is below 0x80 or 0xA2 / 0xA3; any other index runs only when bit (0x800000 >> index) of a1's unlock mask (+159..161) is set, index 17 not with a1 +6 bit 6, index 18 not with a1 +6 bit 7.
- V: the skillset is byte 0 of the job's JobTable row (the image-relative read at 0x14027213C); slots 0..23 are candidates when the other unit has the slot's learned bit (+162 + 3 x index) and a1 has not; skillset 224 drops ability 488 unless a1 +6 bit 6 and ability 491 unless a1 +6 bit 7.
- V: the roll is `Rng_Percent(100, byte_140787F82[8 * ability])` (the ability's learn percent); a zero return marks the slot in the job's three roll bytes (stored at result +24 + 3 x index) and, for abilities up to 0x1FF (the compare at 0x1402721E0), sets bit (ability & 7) of result +94 + ability / 8 and of result +177 + 64 x index + ability / 8.
- V: bit 0 of the result word is set when any slot was marked.
- V (2026-11-09): the job byte +3 of either unit is never read: every row id is 74..92 or a character byte, and the indices stop at 18; the result block holds 19 job entries.
- I: Rng_Percent(100, p) returning 0 is the success case here (the code treats `!Rng_Percent` as learned).

## Notes

The walk, the 19 three-byte roll entries and the 19 64-byte bit sets of the result block are sized for the 19 stock jobs.

Static reading (2026-11-10): the picker (a1) is the unit that has just stopped on the crystal; a1 +79..81 is its own tile (sub_14020435C passes the record of the first scene object's unit). The other unit is the Crystal or Chest unit on that tile (Battle_IsTileOccupied flag 65 matches status Crystal at +0x61 bit 0x40 and Chest at +0x62 bit 0x01). The result block is read by sub_14020435C (word and +92), sub_1402722D8 (the +24 roll bytes, applied to the picker's +162.. bits) and sub_140323D1C (the +94 set, the +158 job ids and the +177 per-job sets, for the window's list); no other code reads it. Layout and readers: see struct CrystalRollResult.

- V: the result block's byte +158 + i is the job id written at 0x140272136 for every index the walk entered; only 8 of each entry's 64 bytes at +177 + 64 x i are cleared at the start (the clear writes one qword per entry), so bits for abilities 64 and above in an entry can survive from an earlier roll; the 512-bit set at +94 is cleared whole.
- V: the walk has no team test; a1 is not checked to be a player unit here.
- V: the unlock mask read at a1 +159..+161 is 24 bits wide (indices 0..23) but only 0..18 are walked.
