# sub_140286A78

- **Address:** `0x140286A78`
- **Area:** [Job data](../areas/job-data.md)
- **Prototype:** `void sub_140286A78(unsigned short unit, int mode)`
- **Callers:** sub_140366FE0
- **Callees:** Party_GetUnitJobId, JobAbilityList_Build, sub_140289F4C

Confidence tags: **V** decoded, **M** measured, **I** inferred, **?** unknown.

## Purpose

Collects the abilities of a party unit's current job into the list buffer used by the job screen, marking each entry that is available to the unit.

## Behavior

- V: the unit index is the first argument and selects the unit record from the party table g_PartyUnits; the unit's job id comes from the 16-bit field at record offset 0x24.
- V: it calls Party_GetUnitJobId for the unit, then calls JobAbilityList_Build 19 times (the unit's own job, then jobs 75..93), accumulating the entries into a 200-word stack array; one call can append up to 24 entries.
- V: after building, it sorts the accumulated words in place with an adjacent-comparison sort.
- V: it then writes the sorted abilities into the shared list buffer at 0x141811470, one 16-bit word per entry, adding 0x4000 to the id when sub_140289F4C returns non-zero and writing the bare id when it returns zero.
- V: the loop stops at the 0xFFFF terminator (compared against -1 held in a register) or at the end of the accumulated list, whichever comes first.
- I: the 0x4000 bit means "known or available", by analogy with the same bit on the shop list where it means "cannot equip" and with the fact that the other branch writes the plain id.
- I: the buffer at 0x141811470 is a general UI list buffer reused by several screens, not a shop-only array, because this job-screen function writes ability ids into it.
- V: sub_140289F4C returns 1 for the small hand-written set of job-specific abilities in 0x1D6..0x1DE: job 15 accepts 0x1D6, 0x1D9, 0x1DD and 0x1DE, and jobs 75, 78, 84 and 89 accept one id each (0x1DA, 0x1D8, 0x1D9, 0x1DD).
- ?: why the stock game marks those innate abilities with 0x4000 in this list; the screen's consumer is not in the exported set.
- V: an entry is marked with 0x4000 when sub_140289F4C reports non-zero: the constant is loaded at 0x140286B7C, ORed at 0x140286B81, and dropped again at 0x140286B89 when the test was zero. The marked word is written to the shared display list.
- V: the insertion sort compares signed 16-bit words (compare at 0x140286B23, signed branch at 0x140286B27), so a 0x4000-marked entry sorts above every plain id; the de-duplication compares raw words at 0x140286B5E and 0x140286B6A, so a marked and an unmarked copy of one id are both kept.
