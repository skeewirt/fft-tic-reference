- **Address:** `0x140033DA4`
- **Area:** [Save data](../areas/save-data.md)
- **Prototype:** `int sub_140033DA4(SaveData *obj, const void *payload, size_t size)`
- **Callers:** `sub_1400C2ED8`, `sub_1400C3258`, `sub_1400C5F8C` (3 sites)
- **Callees:** `sub_140025D74` (CRC-32)

Confidence tags: **V** decoded, **M** measured, **I** inferred, **?** unknown.

## Purpose

The attach check: compares the CRC word the entry header carries with the checksum of the payload that was just inflated, and refuses the entry when they differ.

## Behavior

- V: it compares the stored CRC at object `+12` with the CRC-32 of the payload bytes, header excluded.
- V: on a mismatch it returns an error and the caller leaves the object's buffer as it was, so a damaged entry is never copied into the slot image.
- V: it is called once per attach from the three handlers: the manual-slot handler, the settings handler and one further handler in the same family.
- V: the check is on the payload, not on the container: the PNG chunk's own integrity is libpng's business and the header fields other than the CRC are trusted.
- I: because the check runs before any field is interpreted, a replacement writer that changes the payload without updating the header word is rejected exactly like a corrupted file.
