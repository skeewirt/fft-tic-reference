## Purpose

Post-dispatch step for the physical formulas (id below 7): it filters the pending status set, checks the defender's state and flags the result.

## Behavior

- V: It returns at once unless the context byte at +0x27 is negative.
- V: It builds a two-word request (unit id from +6, then 0xFFFF - the all-ones word is produced by ORing eax with -1, not an immediate) and calls sub_140309FB8 on it.
- V: It reads the defender's HP word at +0x30 and adds the pending amount at +8 before the checks.
- V: It refuses to continue when the defender has +6 & 0xC0, +0x61 & 0x20, a negative byte at +0x62, or +0x64 & 1.
- V: It calls Job_HasMonsterPair and Status_FilterPendingSets, then sub_1403052DC; on success it sets result bit 0x40 and phase 9.
- V: One caller: Battle_ResolveAction, which reaches it only for formula ids below 7.
- V (proposed name Formula_KOTail): it acts only on an HP damage result (R+39 bit 0x80) and works from HP left = the target's HP (+0x30) + R+8 - the clamped R+6 (sub_140309FB8).
- V: with the caster's +0x9A bit 0x40 set and the target not player-flagged (+5 bit 4 clear), a target that would die (HP left below 1, or R+29 bit 0x20) and has a monster pair (Job_HasMonsterPair) gets R+18 |= 0x20 and the byte at 0x1407B07B8 = 6, clearing the knockback and the queued request first.
- V: with the caster's +0x9A bit 0x80 set and the HP left at or below max HP (+0x32) / 5, it sets R+30 bit 0x40, and when Status_FilterPendingSets(0) keeps something it sets R+18 |= 0x40, R+39 |= 8 and the byte at 0x1407B07B8 = 9.
