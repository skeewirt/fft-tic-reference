# sub_140036BD4

- **Address:** `0x140036BD4`
- **Area:** [Save data](../areas/save-data.md)
- **Prototype:** `int sub_140036BD4(const char *area)`
- **Callers:** `sub_1400367F4` (mount machine, one site)
- **Callees:** `sub_1400261CC` (format), `sub_140027EA0`, `sub_140027F98`, `sub_140073810`

Confidence tags: **V** decoded, **M** measured, **I** inferred, **?** unknown.

## Purpose

Deletes the container file of one area: it formats the `%s%s.png` name and removes it through the file layer.

## Behavior

- V: the name formatting and root selection follow the exists and open routines, so the same area name and root give the same path.
- V: it has exactly one caller, the mount machine, which uses it when an area file is present but not usable.
- V: it removes only the container file; slots inside a container are not files, so a slot delete is a rewrite of the whole container, not this call.
- V: a missing file is not an error path here; the mount machine only calls it for a file it has just seen.
- I: this is the repair path of the mount, not a user action, which is why the menu's delete never reaches it.
- ?: whether a failure is reported to the user or only logged was not traced.

## Notes

The one-call-site shape is why the takeover design can neutralise it for the autosave area without touching any menu code.
