## Purpose

Runs the first pending tile event of the flag word dword_142FCE878 (set when a unit has stopped on a tile): crystal or chest pickup, map item, trap and the other terrain events. Only the crystal / chest branch (flag value 1) matters for learning.

## Behavior

- V: it always starts by dispatching battle message 12 with the acting unit's slot (BattleMsg_Dispatch(12, 0, slot, 0, 0, 0)) and sets g_BattleState = 21 (the pickup state, whose per-frame function is sub_14020BFD4).
- V: the flag word is tested in the order 1, 2, 4, 8, 0x10, 0x200, 0x400 (the last two are bit tests that the compiled code does not show as immediates; they read the decompiled `& 0x200` / `& 0x400`), else a fall-through that ends the state (g_BattleState = 49 when sub_140202930 is non-zero, else sub_140203FDC) and returns 0; every other branch returns 1.
- V: flag 1 (a crystal or chest unit on the stopped unit's tile, see sub_140271AC0): the roll is run with the picker's record (g_PreviewUnitTable + 512 x the slot byte at record +444 of the first scene object, found by sub_1402607C0) as its argument, through g_TextCommandSlot (this function first sets that slot to Unit_RollAbilityLearning itself); the result pointer is stored in qword_140D40810.
- V: result word 4 (chest): the item id at result +92 goes to sub_140266890 and message 57 is requested; then BattleMsg_Dispatch(12, ...) shows the choice window when the unit's action-block byte (record +494) has no 0x30 bit, otherwise the item is taken at once with sub_1402722D8(unit, 4).
- V: any other result word (2, 3 or -1): message 27 is requested; when record +494 has a 0x30 bit, or its bit 0x08 is clear, the unit is restored at once with sub_1402722D8(unit, 2) (HP and MP to full) and the action result is applied; otherwise BattleMsg_Dispatch(12, slot, slot, 0, 1, 0) opens the crystal choice window (sub_140324658 case 2) and the outcome comes back later through sub_140237FA4 and sub_14020BFD4.
- V: the branch ends by resetting the crystal's scene unit (SceneUnit_ResetAndQueue4(slot, 4, 31, 0, 0)) and returns 1.
- I: the 0x30 bits of record +494 mark a unit the game controls itself (no choice window), so only a player-controlled unit gets the learn / restore choice; what sets bit 0x08 of that byte was not traced (?).
- I: flag 4 is the map-item branch (sub_140271CA8 gives the item, the discovery notification is sent), flag 8 the trap branch (sub_14030C39C), flag 2 a terrain branch (sub_14030C5A0, Battle_ActorResultLevels); the meaning of 0x10, 0x200 and 0x400 was not decoded here.
- V: the function makes no team test on the unit.
