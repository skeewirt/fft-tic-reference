# sub_14036B5D0

- **Address:** `0x14036B5D0`
- **Area:** [Items and shops](../areas/items.md)
- **Prototype:** `void sub_14036B5D0(int mode)`
- **Callers:** sub_14036B670
- **Callees:** sub_14019879C, sub_140286228, ShopEntry_Fill, sub_1401983E4

Confidence tags: **V** decoded, **M** measured, **I** inferred, **?** unknown.

## Purpose

Refills the shop list's 40-byte row entries from the existing list buffer without rebuilding the item list, used after a change that leaves the ids in place.

## Behavior

- V: the mode is the first argument and is passed straight to the entry filler.
- V: it calls sub_14019879C with the list gadget and a flag derived from the mode not being 1, then sub_140286228 to reorder the list buffer at 0x141811470; the returned count becomes the row count.
- V: it zeroes a 40-byte scratch entry on the stack, then calls ShopEntry_Fill once per row with the row index and the mode.
- V: it ends by tail-jumping into sub_1401983E4, the same gadget refresh that ShopList_BuildEntries uses.
- V: unlike ShopList_BuildEntries it does not call the list sizing helper, so the gadget keeps the size it already has.
- I: this is the lighter rebuild used after a purchase, when the ids and the row count are unchanged and only the counts and prices in the rows need refreshing.
- ?: which event calls it; its only caller is sub_14036B670, whose trigger was not traced.
- ?: whether it can be called while the list is empty; the loop simply runs zero times then.
- V: the sorter call at 0x14036B60B rewrites the shared list in place, then ShopEntry_Fill is called per index; both operate on the current contents, so flags set by the builder are preserved through the sort.
