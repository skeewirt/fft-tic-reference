# sub_140034D7C

- **Address:** `0x140034D7C`
- **Area:** [Save data](../areas/save-data.md)
- **Prototype:** `?` (vtable slot 15 of the save manager)`
- **Callers:** none found — it is installed in the manager's vtable
- **Callees:** `sub_140036D8C` (PNG writer), `sub_14003425C` (inflate), `sub_140073918` (mkdir), `sub_140011750` / `sub_140011804` (alloc / free)

Confidence tags: **V** decoded, **M** measured, **I** inferred, **?** unknown.

## Purpose

The container writer: a multi-state machine that re-reads the existing PNG, adopts every entry it did not queue itself, rebuilds the `UMIF` header and entry table, deflates each entry and writes the picture back.

## Behavior

- V: it is the manager's vtable slot 15 and is never called directly, which is why a direct-call scan finds no callers.
- V: state 4 opens the old `%s.png`, walks its entry table (magic compared at `0x1400352E4`) and appends a record for every name that is not already in its queue, inflating the adopted entry first.
- V: state 5 sums the entry sizes, writes the container header (a 16-byte header plus 32 bytes per entry, magic `UMIF`, version 1, entry count) and calls the PNG writer.
- V: the container body is then scrambled and deflated with the 32 KB preset dictionary, and the PNG chunk is written into the picture.
- V: it creates the save folder before writing (the mkdir helper is called from this routine as well as from the folder builder).
- I: adoption is what makes an extra named entry survive a vanilla save, and what makes the writer's output larger than the number of entries it queued.
- ?: the exact state numbers are from the research table; the machine was not re-walked state by state for this sheet.
