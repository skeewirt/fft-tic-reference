# sub_1400C6008

- **Address:** `0x1400C6008`
- **Area:** [Save data](../areas/save-data.md)
- **Prototype:** `void sub_1400C6008(void *image)`
- **Callers:** `SaveSlots_LoadFromFile`, `sub_1400C33A8` (2 sites)
- **Callees:** `sub_1400C61BC`

Confidence tags: **V** decoded, **M** measured, **I** inferred, **?** unknown.

## Purpose

Fills a 50-slot save image with the empty-slot pattern, so a missing or rejected file reads as 50 empty slots instead of stale bytes.

## Behavior

- V: it writes the empty pattern over the whole `0x1EA488`-byte image; a slot with no valid magic then fails the slot-validity test and is not listed.
- V: it is the first thing the manual-slot loader does, before any entry is requested.
- V: it is also called from the image setup at `sub_1400C33A8`, so the buffer is never left uninitialised.
- V: the pattern is the same one the delete and boot-clear paths use for a slot, so an empty slot from this routine and a deleted slot are indistinguishable.
- I: this is why a corrupt container degrades to "no save data" rather than to an error dialog: the slots simply fail the magic test.
- ?: whether the pattern is all `0xFF` or a per-field pattern; the brief describes an empty-slot pattern rather than a plain fill.
