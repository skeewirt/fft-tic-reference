## Purpose

The resume-order state machine: it walks the three-point ring at boot, requests each point's parts and keeps the newest three points in order.

## Behavior

- V: the state lives at manager `+0x3D5938` and is read from `+0x38`; state 0 clears the index and timestamp arrays.
- V: state 1 requests the next point (`count + 2`) through the read fan-out when fewer than three points are held, then moves to state 2.
- V: state 2 validates the delivered payload (magic `FFTI`, the 0x7A word, a kind below 2) and, when it passes, stores the payload's timestamp word into the ring and increments the count.
- V: state 3 sorts the ring through the order-rebuild helper and writes the new order back.
- V: it is called once, from the title setup, and is therefore the only place the ring is populated at startup.
- I: the ring is a three-slot MRU list: the count, the next index and the timestamps are all that the title needs to offer the newest Continue.
- ?: which scene event creates a new point; the ring proves three rotating points, not when each is captured.
