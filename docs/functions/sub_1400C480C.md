## Purpose

The world-map save step: it flushes any ready resume record and, only when something was queued, kicks the autosave container write.

## Behavior

- V: it delegates the queueing to the map walk and uses its answer to decide whether to write at all.
- V: when something was queued it kicks the `AUTOENHANCED` write (kind 6) and stamps the manager.
- V: it is cheap when nothing is dirty: one map walk and no file work.
- V: two call sites, both on the world map: the screen's own update and the boot update.
- V: the `resume_enwm_main.sav` name itself is produced by the group-1 branch of the per-frame flush, not here.
- I: calling it every update is what makes a world-map position reach the disk without an explicit save.
- ?: which world-map action marks group 1 dirty in the first place.
