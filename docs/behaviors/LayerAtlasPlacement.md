# LayerAtlasPlacement

- **Kind:** observed behaviour
- **Scope:** every layer of a UI frame that is packed (composited, kind 0 or 1, none of the flags +78 / +486 / +488); the Job Tree frame was checked end to end
- **Area:** [Graphics](../areas/graphics.md)
- **Affects:** [UIRender_PrepareLayers](../functions/UIRender_PrepareLayers.md), [GUILayer_PackAtlasRect](../functions/GUILayer_PackAtlasRect.md), [AtlasShelf_Alloc](../functions/AtlasShelf_Alloc.md), [StdSort_LayersByKey](../functions/StdSort_LayersByKey.md), [StdSort_LayersByOrder](../functions/StdSort_LayersByOrder.md), [UILayer_GetTarget](../functions/UILayer_GetTarget.md), [AtlasShelf](../structs/AtlasShelf.md), [GUILayer](../structs/GUILayer.md), [UIManager](../structs/UIManager.md), [UiLayerComposite](../flows/UiLayerComposite.md), [LayerGlowHalfSize](../flows/LayerGlowHalfSize.md)

Confidence tags: **V** decoded, **M** measured, **I** inferred, **?** unknown.

## Summary

Where a UI layer's pixels are placed in the layer atlas each frame: the layers are put in a fixed order (their order key), and a shelf packer places each layer's integer rectangle plus a margin of 2 px (32 px when a blur above 3.2 is present) row by row into pages of the target size; the placed content rectangle P replaces the layer rectangle and P minus the integer screen origin is the atlas offset. The recipe below reproduced x, y and page of all 63 layers of a running Job Tree frame.

## Behavior

- V: inputs. The target size (W, H) = the u16 values at +20 / +22 of UILayer_GetTarget(layer): the layer's own target or the renderer's current one (1280 x 720 for every layer of the live frame; all layers shared one target). Per used layer (byte +76), in slot order (slot = the record index = the order the frame created them in; layer+12 starts as the slot index every frame): the float rectangle (x, y, w, h) at +208..+220, the kind dword +28, the flag bytes +78, +79, +177, +178, +179, +486, +487, +488, +489, and the floats +180, +188, +500.
- V: step 1, order. With no masked layer (+487 clear everywhere, the common case) each layer's order o starts as its slot index and is then replaced, walking the list from the last layer down: q = the nearest layer below it in the list whose float rectangle overlaps its own (strict: q.x + q.w > x, x + w > q.x, the same for y, in float32); if there is one, o = (the slot index of q) + 1 (the lower layer's own index, not its renumbered one, because the walk goes top down); otherwise o stays its slot index. A layer therefore sits right after the nearest lower layer it overlaps, or keeps its own place.
- V: step 2, key. key = mode | (4 x o + 4) with mode = 0 for kind != 0, else 1 when the drop-shadow byte +177 or the glow byte +178 is set, else 2. Keys are compared as unsigned dwords. The layers are sorted by key with MSVC's std::sort (StdSort_LayersByKey): up to 32 layers it is a stable insertion sort; with more it is the introsort whose partition (median of three up to 41 elements, Tukey ninther with step n >> 3 above, three-way partition) is not stable, so equal keys can swap (live: slots 58 and 51 with key 206 came out 58, 51). Then +12 is renumbered 1, 2, 3 ... by key change (equal keys share a number). The packing order is this sorted list.
- V: step 3, the rare cases that change the order. A layer with +489 (mask source) is culled (+79 = 1, no packing, +16 = +20 = -1) when its rectangle does not overlap the nearest lower layer that has +487. A frame with +487 layers also runs a temporary allocation over the +487 layers (margin as below; at each temporary page break the later layers get +20 = the breaking layer's +12) and a third top-down pass that sets o = (o of the nearest overlapping lower layer) + 1 when that layer is a +487 layer with +179 set, kind != 2 and +78 / +486 / +488 clear, and o = 0 for a +487 layer that overlaps nothing; the overlap pass of step 1 then adds +20 to its result. None of this occurred in the live frame; it is read in the code only.
- V: step 4, the integer rectangle. For each layer in list order, not culled: (x0, y0, x1, y1) = ((int)x, (int)y, (int)(x + w), (int)(y + h)) (float32 sum, conversion truncates toward zero); w' = x1 - x0, h' = y1 - y0. margin m0 = 32 when |float +500| > 3.2 or float +180 > 3.2 or float +188 > 3.2, else 2.
- V: step 5, the shelf (the primary shelf, page size W x H). State {cx, ry, rh, page} starts at {0, 0, 0, 0} each frame. For a layer that is packed (+179 set, kind <= 1, +78 / +486 / +488 clear) and has w' > 0 and h' > 0: mx = max(0, min(m0, trunc((W - w') / 2))), my = max(0, min(m0, trunc((H - h') / 2))); pw = w' + 2 mx, ph = h' + 2 my. (a) if cx + pw + 3 > W: ry += rh, rh = 0, cx = 0. (b) if ry + ph + 3 > H: page += 1, cx = 0, ry = 0, rh = 0. (c) x = cx + mx, y = ry + my. (d) if x0 is a multiple of 4 and x > 0 and x is not: padx = the distance up to the next multiple of 4, x += padx (else padx = 0); likewise pady for y with y0. (e) P = (x, y, x + w', y + h'); cx += padx + pw; rh = max(rh, ph + pady). The layer gets +16 = page, +208 / +212 = (float)x / (float)y, +216 / +220 = w' / h' as floats, +224 / +228 = x - x0 and y - y0 (the atlas offset: atlas pixel = screen pixel + offset), +240..+252 = the integer rectangle, +492 = 1. The content origin is P itself: the margin lies around it inside the pw x ph block that starts at (cx_before + padx, ry), so a layer with margin 32 at the start of a page has x = 32, y = 32.
- V: step 6, special rectangles. A layer with w' <= 0 or h' <= 0 (the integer rectangle is empty) is returned unchanged: P = its integer rectangle, offset 0, the shelf does not move, +16 = the current page (live: layers of width 0 keep their screen y as atlas y). A layer that is not packed (+179 clear, kind > 1, or +78 / +486 / +488 set) allocates the whole page rectangle (0, 0, W, H): the margin is clamped to 0, both fit tests fail, so it takes a new page (page += 1, shelf left at cx = W, ry = 0, rh = H) and the next layer after it starts yet another page; its +16 = that page, its rectangle is not rewritten (+492 = 0).
- V: step 7, masked layers (+487, read in the code only). The same rectangle goes first to the secondary shelf (own state {0, 0, 0, 0}, same margin, same alignment key, same rules) giving P2 and +20 = the secondary page; when the secondary page changed, the primary shelf is first moved to a new page (page += 1, cx = ry = rh = 0); then the primary placement runs as in step 5. +232 / +236 = P2 - (x0, y0), else = +224 / +228.
- V: parity. The 2 x 2 box grid of RT 26 is anchored at the atlas origin, so the layer's pixel column i (from x0) sits at atlas column P.x + i and the cell grid pairs it with its right neighbour when P.x is even (same for rows with P.y). If x0 is a multiple of 4 and P.x > 0, P.x is a multiple of 4 (always even); if y0 is a multiple of 4 and P.y > 0, P.y is a multiple of 4. Otherwise P.x = (the sum over the earlier layers of the same row of w' + 2 m + padx) + m + 0, and since every margin is even, the parity of P.x is the parity of the sum of the earlier widths in the row plus their pads; P.y = (the sum of the earlier rows' heights, each the maximum of h' + 2 m + pady in the row) + m + pady. The first layer of a page starts at cx = 0, ry = 0.
- V (live 2026-10-30): worked check. Page 0 of the frame: slot 0, integer rectangle (44, 129, 150, 196), margin 32 (blur 6.0): x = 0 + 32 = 32 (44 is a multiple of 4: nothing to add), y = 32, P = (32, 32, 138, 99), cx = 106 + 64 = 170, offset (-12, -97); slot 1 has width 0 (rectangle (0, 253, 0, 308)): unchanged; slot 2 (595, 248, 692, 303), margin 32: x = 170 + 32 = 202 (595 is not a multiple of 4), y = 32 + 0 = 32, offset (-393, -216); slot 3 (603, 254, 684, 297): x = 170 + 97 + 64 + 32 = 363. All 63 layers match in x, y and page, 5 pages, margins of 2 and 32, rows opened by the x test and pages by the y test, and the alignment of 4-aligned origins.

## Notes

The checked frame was the idle Job Tree: slots 63 and above in the layer table held stale records (their +16 / +208 values are from older frames) and are not part of the list; the list array beyond the live entries also keeps stale entries (the count at +172 is cleared after the frame). A renderer that wants the atlas position of a layer needs only steps 4 to 6 once the packing order is known; the order depends on the overlap test, on the shadow / glow flags and on the sort's tie behaviour, so a frame with equal keys among more than 32 layers must follow the partition code (the sheets of the two std::sort loops and their partition helpers).
