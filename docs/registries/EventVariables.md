# EventVariables

- **Kind:** registry
- **Area:** [Event system](../areas/event-system.md)
- **Resolved by:** [EventVar_Read](../functions/EventVar_Read.md), [EventVar_Write](../functions/EventVar_Write.md), [EventVar_Alu](../functions/EventVar_Alu.md), [EventVar_ResolveSlot](../functions/EventVar_ResolveSlot.md), [SceneVar_Read](../functions/SceneVar_Read.md), [SceneVar_Write](../functions/SceneVar_Write.md), [SceneVar_Alu](../functions/SceneVar_Alu.md)

Confidence tags: **V** decoded, **M** measured, **I** inferred, **?** unknown.

## Summary

The event variable space: 1024 ids that the event scripts, the world map, the menus and the battle loader read and write through one accessor. This registry lists the ids whose meaning comes from code: the whole numbers 0..127 (registers, view state, calendar, battle setup), the flags 128..511 that code or event scripts name, and the special ids elsewhere (the write lock 508, the scenario and test-battle flags, one id inside the rumour block). The ranges that mirror a game table are rules in EventVariableRanges. Ids 0..127 are dwords, the rest single bits unless an entry says otherwise; the whole space is packed in one store.

## Behavior

- V: ids of 1024 or more stop the running event script with an error; every id below it resolves to a dword, a bit or a nibble slot of the store.
- V: while variable 508 is non-zero only part of the space accepts writes (see EventVariableWriteLock).
- I: the ids 0..127 are the working half of the space (scratch registers, view state, calendar, battle setup); the bits from 128 up hold the story state. This rests on which ids the code reads versus which ids scripts write.
- ?: ids 81, 83, 86, 99, 105, 145, 146, 148, 156, 161 and 759 are used by code, but a settled meaning was not found.
